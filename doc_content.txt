Tổng quan tính năng Routines là module lõi của Healthy Path, cho phép người dùng xây dựng và duy trì các thói quen sức khỏe hằng ngày. Module bao gồm thư viện bài tập do admin quản lý, hệ thống lên lịch cá nhân, theo dõi trạng thái thực thi, gamification (streak, điểm, badge) và engine AI gợi ý thích nghi. 1.1 Mục tiêu sản phẩm Giúp người dùng hình thành thói quen lành mạnh bền vững thông qua nhắc nhở thông minh và phản hồi tức thì. Tăng Daily Active Users bằng check-in streak và gamification. Cung cấp dữ liệu hành vi đủ sâu để AI personalization hoạt động hiệu quả sau 14 ngày. Tích hợp mượt với module Group Challenge để thúc đẩy động lực xã hội. 1.2 Phạm vi Trong phạm vi (In-scope) Ngoài phạm vi (Out-of-scope) Tạo, sửa, xoá routine (admin &amp; user) Video hướng dẫn trong routine Lên lịch &amp; nhắc nhở thông minh Social feed chia sẻ routine công khai Tracking trạng thái thực thi Marketplace mua/bán routine Streak, điểm, badge, group challenge Live session với chuyên gia AI gợi ý dựa trên mood &amp; lịch sử Wearable auto-sync (phase sau) 2. Kiến trúc dữ liệu 2.1 Các bảng liên quan Module Routines sử dụng 2 bảng chính trong schema PostgreSQL: Bảng routines — thư viện tĩnh Cột Kiểu dữ liệu Ràng buộc Mô tả id UUID PK Khoá chính, gen_random_uuid() title VARCHAR(200) NOT NULL Tên bài tập description TEXT Mô tả chi tiết category VARCHAR(50) CHECK yoga, meditation, reading, breathing, exercise, other duration_minutes INT NOT NULL Thời lượng mặc định (phút) difficulty VARCHAR(20) CHECK nhe, trung_binh, kho — ảnh hưởng điểm &amp; AI thumbnail_url TEXT Ảnh đại diện is_system BOOLEAN DEFAULT FALSE TRUE = do admin tạo, user không xoá được is_premium BOOLEAN DEFAULT FALSE TRUE = chặn user Free, hiện upsell created_by UUID FK → users NULL nếu is_system=true deleted_at TIMESTAMPTZ Soft delete NULL = chưa xoá created_at / updated_at TIMESTAMPTZ NOT NULL Auto-trigger updated_at Bảng user_routines — bản ghi thực thi Cột Kiểu dữ liệu Ràng buộc Mô tả id UUID PK Khoá chính user_id UUID FK → users Người dùng thực thi routine_id UUID FK → routines Bài tập được ánh xạ status VARCHAR(20) CHECK pending, in_progress, paused, completed, skipped scheduled_at TIMESTAMPTZ Thời điểm lên lịch started_at TIMESTAMPTZ Ghi khi user bấm Start completed_at TIMESTAMPTZ Ghi khi hoàn thành actual_duration_minutes INT Thời gian thực tế (tính từ started→completed) score_earned INT DEFAULT 0 Điểm tích lũy sau khi hoàn thành deleted_at TIMESTAMPTZ Soft delete NULL = chưa xoá created_at / updated_at TIMESTAMPTZ NOT NULL Auto-trigger updated_at Quy tắc thiết kế quan trọng Mỗi lần user lên lịch tạo một bản ghi user_routines mới — không bao giờ tái sử dụng bản ghi cũ. Điều này đảm bảo audit trail đầy đủ và cho phép phân tích lịch sử chính xác. 3. Luồng tạo &amp; cấu hình Routine 3.1 Nguồn tạo routine Có ba nguồn tạo routine trong hệ thống: Nguồn is_system Mô tả &amp; quyền System routine TRUE Admin tạo qua Web Admin. User chỉ có thể thêm vào lịch cá nhân, không sửa/xoá được. Hiển thị cho tất cả user theo tier. User routine FALSE User tự tạo trong app. Cho phép sửa, xoá (soft delete). Chỉ hiện trong lịch của user đó. AI gợi ý FALSE AI sinh ra dựa trên mood &amp; lịch sử. User bấm &apos;Thêm vào lịch&apos; → tạo user_routines với scheduled_at = thời điểm AI đề xuất. 3.2 Premium gate logic Khi user Free cố gắng bắt đầu routine có is_premium=true: API kiểm tra subscription hiện tại của user — query user_subscriptions WHERE status=&apos;active&apos; AND plan = premium. Nếu không có subscription phù hợp → trả về HTTP 403 với error_code=PREMIUM_REQUIRED. Client hiển thị modal upsell với CTA &apos;Nâng cấp Premium&apos;. Không tạo bản ghi user_routines. Lưu ý Không ẩn hoàn toàn routine premium khỏi danh sách — hiển thị nhưng khoá để user biết nội dung có sẵn khi nâng cấp (freemium best practice). 4. Scheduling &amp; Nhắc nhở 4.1 Cơ chế lên lịch Hệ thống hỗ trợ hai chế độ lên lịch: Chế độ Cách hoạt động Trigger tạo user_routines One-time User chọn ngày giờ cụ thể. Ngay lập tức khi user xác nhận. Recurring User chọn các ngày trong tuần + giờ. Hệ thống tự tạo bản ghi mỗi ngày. Cron job 00:00 UTC+7 mỗi ngày. 4.2 Recurring cron job Logic cron 00:00 hằng ngày Query tất cả recurring_templates (bảng phụ lưu cấu hình lặp) của user còn active. Với mỗi template khớp ngày hôm nay (thứ trong tuần), kiểm tra UNIQUE constraint: SELECT 1 FROM user_routines WHERE user_id=? AND routine_id=? AND DATE(scheduled_at)=CURRENT_DATE. Nếu chưa tồn tại → INSERT user_routines với status=pending, scheduled_at = ngày hôm nay + giờ từ template. Sau khi insert → enqueue notification job vào queue với fire_at = scheduled_at - INTERVAL &apos;10 minutes&apos;. Idempotency Cron job phải idempotent — chạy lại không tạo bản ghi trùng. UNIQUE INDEX ON user_routines(user_id, routine_id, DATE(scheduled_at)) đảm bảo điều này. 4.3 Smart reminder — logic nhắc nhở Thời điểm gửi push notification được tính như sau: Điều kiện Hành động fire_at nằm trong quiet_from → quiet_until Dời fire_at sang quiet_until của ngày hôm đó. fire_at đã qua (scheduled_at đã gần) Gửi ngay lập tức nếu &lt; 5 phút trước scheduled_at. user_id không có FCM/APNs token Bỏ qua push, ghi log missed_push. Không báo lỗi cho user. Routine bị xoá (deleted_at IS NOT NULL) Huỷ notification job nếu chưa gửi. 4.4 Reschedule Khi user thay đổi giờ của routine đã lên lịch: UPDATE user_routines SET scheduled_at=? WHERE id=? AND status=&apos;pending&apos;. Tìm notification job đang chờ trong queue theo user_routine_id → DELETE. Tạo notification job mới với fire_at mới (áp dụng lại quiet hours check). Không tạo bản ghi user_routines mới — chỉ cập nhật bản ghi hiện tại. 5. Trạng thái thực thi — State Machine 5.1 Các trạng thái Trạng thái Chuyển từ Mô tả pending — Bản ghi vừa tạo, chưa được bắt đầu. in_progress pending User bấm Start. Ghi started_at = NOW(). paused in_progress User bấm Tạm dừng giữa chừng. Lưu elapsed_seconds. completed in_progress / paused User hoàn thành. Ghi completed_at, tính điểm. skipped pending / in_progress User bỏ qua chủ động hoặc cron job quét quá hạn. 5.2 Chuyển trạng thái &amp; điều kiện Chuyển Trigger Điều kiện bắt buộc pending → in_progress User bấm Start status == &apos;pending&apos; HOẶC status == &apos;paused&apos; in_progress → paused User bấm Tạm dừng status == &apos;in_progress&apos; in_progress → completed User bấm Hoàn thành status == &apos;in_progress&apos;, elapsed &gt;= 50% duration any → skipped User bỏ qua / cron 23:50 status IN (&apos;pending&apos;, &apos;in_progress&apos;, &apos;paused&apos;) completed → (không đổi) — Trạng thái cuối, không thể hoàn tác. Quy tắc 50% Routine chỉ được mark completed nếu user đã thực hiện ít nhất 50% duration_minutes. Nếu dưới ngưỡng, API trả về lỗi INSUFFICIENT_DURATION và gợi ý user tiếp tục. Điều này ngăn click gian lận để lấy điểm. 5.3 Miss detection — cron 23:50 Cron job chạy lúc 23:50 mỗi ngày thực hiện: SELECT * FROM user_routines WHERE status IN (&apos;pending&apos;,&apos;in_progress&apos;,&apos;paused&apos;) AND DATE(scheduled_at) = CURRENT_DATE. Với mỗi bản ghi tìm được → UPDATE status = &apos;skipped&apos;, updated_at = NOW(). Không gửi notification cho miss thụ động — tránh làm user cảm thấy bị trách mắng. Ghi vào audit_logs để phân tích tỉ lệ miss theo category/time slot. 6. Gamification — Streak, Điểm &amp; Badge 6.1 Streak logic Streak tính theo ngày, không theo số lượng bài hoàn thành: Điều kiện giữ streak: ít nhất 1 user_routines có status=&apos;completed&apos; trong ngày. Streak reset về 0 nếu không có bài nào completed trong ngày (kể cả nếu có skipped). Streak không bị ảnh hưởng bởi số lượng bài skip — chỉ cần 1 completed là đủ. Bảng user_stats (mở rộng schema) Cột Kiểu Mô tả streak_current INT Số ngày streak liên tiếp hiện tại. streak_best INT Kỷ lục streak cao nhất từ trước đến nay. streak_updated_date DATE Ngày cuối cùng streak được cập nhật (để cron check). total_score BIGINT Tổng điểm tích lũy toàn thời gian. ai_insights JSONB Dữ liệu AI phân tích hành vi, review mỗi 7 ngày. 6.2 Hệ thống điểm Điểm tính mỗi bài hoàn thành theo công thức: score = duration_minutes × difficulty_multiplier Độ khó Multiplier nhe 1.0× trung_binh 1.5× kho 2.0× Điểm được cộng vào: user_stats.total_score — điểm cá nhân tổng thể. challenge_participants.score — điểm trong group challenge đang tham gia (nếu có). 6.3 Streak milestone &amp; Badge Milestone Badge Hành động 3 ngày Spark Push notification đặc biệt + badge unlock. 7 ngày Week Warrior Push + badge + hiện lên profile. 14 ngày Fortnight Focus Push + badge + mở gợi ý AI level cao hơn. 30 ngày Monthly Master Push + badge + tháng Premium miễn phí (A/B test). 60 ngày Iron Habit Push + badge đặc biệt + hiện leaderboard bạn bè. 100 ngày Century Club Push + badge hiếm + thông báo toàn nhóm. 7. Trước ngưỡng này, fallback về gợi ý theo category phổ biến nhất của toàn hệ thống. 7.2 Input của engine Nguồn dữ liệu Dữ liệu lấy mood_checkins mood + energy_level của check-in gần nhất trong ngày. user_routines (14 ngày) Tần suất hoàn thành theo category, tỉ lệ skip, giờ thực hiện phổ biến. wearable data (optional) HRV, bước chân, chất lượng giấc ngủ đêm qua. user_stats.ai_insights Kết quả review 7 ngày trước (tránh tính lại từ đầu). 7.3 Output của engine Top 3 routine gợi ý cho ngày hôm nay — đã lọc bài trùng lịch và bài user thường skip.
